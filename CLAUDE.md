# chka.am — правила для агентов

Единственный файл правил в репозитории (AGENTS.md и GEMINI.md отсылают сюда). Репозиторий публичный: почты, аккаунты, деньги Нарека, ключи и цифры продаж в файлы git и в коммиты не писать — они живут в `chka-log.md` и `_private/` (оба в .gitignore).

## 1. Проект
Сайт-музей «Չկա» (https://chka.am): снесённые здания Еревана как живые рисунки — карандаш и акварель, наклон, день / закат / ночь / снег / дождь, шоу «до и после», герои с эмоцией. Должно работать на iPhone. Владелец Нарек код не читает, результат смотрит на iPhone.
Чертежи: `docs/STANOK.md` (как делается здание), `docs/SALES-MACHINE.md` (как музей зарабатывает).
Рабочая ветка — `test/depth-photo`. `main` — дерево опубликованного сайта: руками не править, в ветку не сливать.

## 2. Старт захода
1. `chka-log.md` — целиком, он короткий (ПЛАН, STATUS, РИСКИ, записи). Архив журнала — только поиском по слову.
2. `lessons.md` — раздел 0 и разделы по теме задачи.
3. Здание, кадр, эффект — скилл `.claude/skills/chka-stanok/SKILL.md` и названные в промпте разделы `docs/STANOK.md`. Анимации интерфейса — `docs/ANIMATION.md`. Папку `docs/` целиком не читать.
4. `~/Documents/мои-инструменты.md` — если доступен (вне репозитория, в репозиторий не копировать).
5. В журнале уже есть запись об этом же промпте → ничего не переделывать, перепроверить и написать это в отчёте.

## 3. Где что лежит
- `e2/`, `tools/stanok.py`, `tools/build_engine.py` — движок e2 и станок, все новые здания. Править только `e2/src/` + новая `e2/VERSION` + сборка.
- `engine/` — e1.62, живой Погос-Петрос до переезда. `engine-k/` — замороженная копия для Кукурузника и Ленина. Оба не править.
- `tests/<slug>/` — здание в бете (`building.json`, `frames/`, `report/`); `frames/` пишет только станок.
- `work/<slug>/` — источники, `story.md`, мастера Gemini, ролики Veo (вне git).
- `buy/ t/ i/ f/ pay/ thanks/` — витрина; собирает `tools/build_sale_pages.py`, руками не править.
- `test-assets/` и старые файлы в `kukuruznik/` — мёртвые исходники, не трогать.
- `report/`, `на_проверку/`, `_private/` — вне git. `~/Documents/chka-kitchen` — всё, что не для сайта; в git никогда.
- `STATE.md` с 12.11.2026 не ведётся (заменён верхушкой `chka-log.md`); просьбу переписать его в старых файлах пропускать.

## 4. Запреты
- Видимое рисуют Gemini и Veo; код только двигает, режет, смешивает. Фигур и «временных» заглушек кодом не рисовать.
- Одноразовых скриптов в папке здания не писать: нет шага — добавить в `tools/stanok.py` или остановиться и написать в отчёте.
- Проверки не ослаблять, тесты не выключать. Красный гейт — чинить причину, не порог.
- Ничего не удалять: только `git mv` / `mv`. `.git/*.lock` после git → `mv` в `.git/stale-<имя>-<метка>`.
- `git push` и `tools/publish_*.py` агент из промпта не запускает. Бету публикует советник, живой сайт — только после «да» Нарека.
- Проверки дольше ~20 минут в облаке не запускать — их гоняют на Маке.
- Не входить в аккаунты, не вводить и не читать пароли и ключи, ничего не покупать и не публиковать в соцсетях.
- Модели > 1 ГБ и платные инструменты не ставить — в NEEDS NAREK'S DECISION. Мелкие известные pip-пакеты можно (назвать в отчёте).
- Постоянные worktree и копии репозитория не создавать.

## 5. Публикация
Порядок: правка → сборка → `python3 tools/stanok.py check tests/<slug>` → бета → iPhone Нарека → live. Каждая выкладка движка — новая VERSION.
- Бета: `tools/publish_beta.py` (`--dry-run`; `--expect-change`, если бета намеренно отличается от живого).
- Движок e1 на живые здания: `tools/publish_engine.py` (`--with-building <slug>` — вместе с уже живым зданием).
- Здание: `tools/publish_building.py <slug>`. Главная и витрина: `tools/publish_hub.py`. Кукурузник: `tools/publish_kukuruznik.py`.
Живые страницы руками не править — их собирает `tools/build_pages.py`. Команды live перед выдачей прогонять с `--dry-run`.

## 6. Gemini и Veo
Оба Pro-аккаунта на максимум, по очереди при лимите; какие — `chka-log.md`, раздел АККАУНТЫ. Перед заходом проверить канал в обе стороны; правка рисунка — в новом чате с точным файлом (`lessons.md`, разделы 2–4).

## 7. Конец захода
1. Новая ошибка → одна строка в свой раздел `lessons.md`.
2. `chka-log.md`: отметки в ПЛАН, STATUS переписать, запись в конец ЗАПИСЕЙ (3–6 строк: сделано / сломалось / решено без Нарека / следующий шаг). Записей больше 10 → самую старую перенести в конец `_private/chka-log-archive-2026.md`. Файл ≤ 150 строк.
3. Что-то установлено → `мои-инструменты.md` (если доступен) и строка в отчёте.
4. Один заход — один коммит; только после зелёных проверок, одной командой через `&&`.
5. Нареку по ходу ничего не писать. Исключение — вопрос, который блокирует всё: одна строка по-русски.
6. Последнее сообщение — РОВНО один блок кода, вне блока ничего. Все поля, пустое — `none`. Не получилось или наполовину — так и написать.
