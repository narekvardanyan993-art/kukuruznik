# Станок chka.am — как сделать здание

Полная спецификация: `docs/STANOK.md` (разделы в скобках). Этот файл — только порядок и запреты.
Состояние: спецификация готова 10.11.2026; команды `tools/stanok.py` появляются по прогонам П0–П7 (§7).
Команды ещё нет → НЕ писать одноразовый скрипт в папку здания: добавить шаг в `tools/stanok.py` или остановиться и написать в отчёте.

## Перед началом
1. Прочитать `STATE.md`, в `chka-log.md` — только PLAN и STATUS. `lessons.md` — поиском по слову.
2. `python3 tools/stanok.py check --selftest` — гейты сами себя проверяют. Красная самопроверка = сначала чинить гейт.
3. Перед заходом с Gemini/Veo: `stanok channel` (файл туда-обратно, sha). Gemini — только аккаунт pro.gemini.one1.

## Где что лежит (§1.1)
- `work/<slug>/` — источники, `story.md`, мастера `masters/<кадр>/{day,bg,night,sunset,snow}.png`, вставки, ролики Veo, `journal.json`. В git не идёт.
- `tests/<slug>/building.json` (format 2) и `tests/<slug>/frames/` + `manifest.json` — пишет только станок.
- `tests/<slug>/report/` — листы снимков и отчёт гейтов.
- `engine-k/` — замороженный движок e1.62 Кукурузника и Ленина, не трогать. Полигон e2 — только Погос-Петрос.

## Порядок (§1.2)
| Шаг | Команда | Готово, когда |
|---|---|---|
| S0 источники | `stanok init <slug>` + pastvu/Wikimedia | у каждого ракурса снимок того же города и эпохи; нет источника — нет ракурса |
| S1 текст | `work/<slug>/story.md` | 5–6 ракурсов, факты с источником hy/ru/en, ≥ 2 изюминки с вариантами дождь и снег, сценарий до/после, список промптов |

| S3 версии | Gemini-правка в НОВОМ чате с точным файлом → `stanok intake bg|night|snow` | G9: сдвиг ≤ 1 px, нет чужой луны |
| S4 слои | `stanok layers <slug>` | G2, G11 |
| S5 герои, до/после | Veo → `stanok actor`, `stanok show` | G10; герой виден на всех 5 кнопках |

| S7 настройки | `stanok config` + точки и тексты | G8 |

Цель: ≤ 3 захода агента (S0–S2 · S3–S5 · S6–S9) и ≤ 1 час Нарека.

## Запреты (§0, §4)
- Видимое рисуют Gemini и Veo. Кодом — только небо (облака, птицы), огни, осадки.
- Один эффект — один режим. Нужен «особый режим под здание» → эффект на этом кадре выключить.
- Мелкое движение — качественно (ролик Veo, прошедший гейты) или никак. Машин нет, звуков нет, воды и людей кодом нет, стоящих людей нет.
- Файлы в `frames/` руками не править. Любая правка рисунка — `stanok insert` (иначе пропадёт на закате или ночью).
- Движок не править скриптом-заменой строк; только `engine/src/` + новая VERSION.
- Вход Veo — вырезка без увеличения, первый кадр = последний = рисунок. Слово «fountain» на пустой площади не писать.
- Крупные планы и интерьеры — `kind: close|interior` (почти плоско, в интерьере погоды нет).
- Надписи и вставки — не на святое (стены церкви, портал, алтарь); запретные зоны в `story.md`.
- `git push`, `tools/publish_*.py`, проверки дольше 20 мин — не агент. После git в VM остался `.git/*.lock` → `mv` в `.git/stale-…`, не удалять.

## Гейты (§6) — что обязано быть зелёным
- Новая бета: все G1–G13.
- Правка одного кадра: G3, G5, G7, G13 этого кадра (`stanok check <slug> --frames <кадр>`).
- Правка движка: самопроверка всех гейтов + «до/после» по живым зданиям (`stanok look`, §2.4).

| Гейт | Ловит |
|---|---|
| G1 | ветер размазывает фон |
| G2 | кайма вырезки, вырезка на весь кадр |
| G3 | вставка не во всех версиях кадра |
| G4 | fps на слабом телефоне |
| G5 | кэш и версия движка |
| G6 | движение мимо виртуальных часов |
| G7 | 5 кнопок на 390×844: День, Закат, Ночь, Снег, Дождь; герой виден и не закрыт интерфейсом |
| G8 | схема building.json падает громко; ≥ 2 изюминки |
| G9 | версии кадра сдвинуты |
| G10 | мёртвый кадр (< 2 % движения) |
| G11 | белые края и «резина» при наклоне |
| G12 | панель ≤ 300 мс, плашка уходит через 3 с |
| G13 | файл не доехал (manifest) |

## Если гейт красный
1. Читать `tests/<slug>/report/gates.md` — там кадр, кнопка, снимок.
2. Чинить причину, а не порог. Порог меняется только с записью в `lessons.md` «почему».
3. Не получилось за заход — так и написать в отчёте; на бету красное не выкладывать.

## В конце захода
- `chka-log.md`: PLAN (отметки), STATUS, запись с датой: сделано / сломалось / следующий шаг.
- `STATE.md` переписать (≤ 60 строк). Новая ошибка → строка в `lessons.md`.
- Последнее сообщение — один блок кода AGENT REPORT (формат в инструкциях проекта).
