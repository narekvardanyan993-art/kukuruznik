## 3. Фигуры не двигаются на iPhone

| подозрение | вывод |
|---|---|
| Маска в альфе карты окружения (premultiplied alpha в iOS) | НЕ причина: карта окружения грузится в GPU типизированным массивом (`engine/prep.js prepareEnv` → `texImage2D(..., Uint8Array)`), премультипликации нет ни в одном браузере |
| `CONFIG.FIGURES` не доходит до страницы | НЕ причина: в опубликованной бете (`main 6530f40`, `beta/tests/lenin/index.html`) есть `FIGURES` и пять `_fig.png` |
| **Размер движения** | **главная причина**: движение s18 задано в px КАДРА (сидящий 0,55–0,85 px, клевок 1–1,5 px, рука 1,6–2,2 px), а кадр 768 px на телефоне ≈ 0,62 css px на px кадра → 0,3–1,3 css px. Глазом не видно |
| Экономия по fps (`perfLevel 2`) | возможная причина на телефоне: при двух провалах fps фигуры выключались навсегда (`fx.figOn … perfLevel < 2`) — убрано |
| «Уменьшить движение» в iOS | фигуры по-прежнему стоят (как облака и дыхание) — теперь это видно в `?debug=1` |
| Лимит uniform-векторов | на старых/слабых GPU шейдер с 24 фигурами (96 векторов) мог не собраться → вся сцена в запасной режим; теперь фигур столько, сколько влезает |

Исправлено: движок e1.23 — у фигуры восьмое число «множитель движения» (x и рука/клюв ×k, вертикаль ×√k), фигуры не зависят от экономии fps,
защита по лимиту uniform; `source/s19/figs19.py` — множитель от размера и типа (сидящие 4,1–4,5, нарды 1,7–2,3, стоящие 1,5–2,8, голуби 1,2–2,4,
шарик 1,2–2,5, листья/трава 1,6) и маска/рамка шире на наибольший сдвиг + 1 px. Наибольший сдвиг в рендере 5,6 px кадра (≈3,5 css px), в s18 — до 2,2.
Снимки 3 с подряд: сдвинулись 8/20, 17/23, 7/18, 3/6, 17/24 фигур (`snap_summary.md`, `motion_day_f*_m0_m1_diff.jpg`).
