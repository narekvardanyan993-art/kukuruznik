## 2. Gemini: рисунки и правки
- Правка кадра — в НОВОМ чате с точным файлом во вложении; «edit the FIRST image in this chat» в длинном чате берёт не ту картинку и перекомпонует кадр. [заход 9 · L208]
- Правка целого кадра перерисовывает ВСЁ (люди крупнее, газон вместо мостовой, сдвиг линий): брать только новые объекты в пустых местах — отличие по штриху, отбраковка крупных и обрывков (gpaste.py). [s17 · L101]
- «Добавь человека» перерисовывает облака и оттенок: вписывать только область фигуры по разнице в узкой рамке; рамку сначала широкую, потом сужать. [27.10 · L193]
- Позы фигур — Flash-правка квадратной вырезки 1:1 вокруг фигуры (совпадает без сдвига); вторая поза — новый чат с первым ответом во вложении. [заход 9 · L209]
- Мелкую статую на виде сверху Gemini укрупняет и даёт ореол: слать кусок ×5 вокруг неё, вклеивать с совмещением ECC. [s20 · L118]
- Силуэт объекта из ответа — отличие от исходника (ΔE Lab > 12), а не альфа патча: альфа — сплошное пятно вокруг группы. [s18 · L105]
- Отдельный предмет (лист, фрагмент) Gemini рисует на однотонном фоне, вписывает агент. [без метки · L9]
- Патчи и фрагменты хранить только в PNG: JPEG портит края. [без метки · L10]
- Белый фон листа убирать заливкой от краёв клетки; закрытые просветы — только у сценок (`--holes`), иначе пропадают блики. [без метки · L46]
- Вырезка с однотонного фона оставляет ореол (у луны — тёмное кольцо): резать по светлому ядру (`cut6 --disc --feather`), проверять на трёх фонах. [pp-4d · L199]
- Вывеску или надпись кодом «без следов» не убрать: правка Gemini «remove all the letters… no other changes», пока кадр не разобран на слои. [pp-4 · L184]
- В режиме картинок Gemini иногда отвечает текстом: начинать с «Generate an image.», при тексте — «Now draw it…, no text answer». [pp-3b · L183]

## 3. Gemini/Veo: канал, браузер, лимиты
- Перед заходом проверить канал в ОБЕ стороны (загрузка и скачивание). Рабочее: расширение Chrome в сети, либо развёрнутое окно Claude, либо доступ к ~/Downloads. Без канала лимит вслепую не тратить. [заход 9 · L206]
- Claude in Chrome может быть не подключён или Chrome закрыт: у задачи с Gemini всегда запасной путь без браузера; в отчёте честно «Gemini не было». [07.10, s32 · L40, L168]
- Chrome закрыт (`list_connected_browsers` пуст) → открыть через `computer_open_application`; расширение в сети через пару секунд. [pp-3 · L180]
- Загрузка файла в Gemini: перехват `HTMLInputElement.click` (type=file: input в DOM + aria-label, окно не открывать) → «Загрузить файлы» → find → `file_upload` путём `/mnt/user-data/uploads/…` (сначала `device_stage_files`). Путь Мака, outputs и `.git/…` расширение не берёт. [s8, s17, 27.10, заход 9 · L66, L102, L192, L207]
- Текст запроса: `focus()` на `rich-textarea .ql-editor` → `document.execCommand('insertText')`, длину сверить по innerText; синтетический paste игнорируется; ответ читать кусками ≤ 1500 знаков. [pp-22 · L249]
- Нет `file_upload`: кадр на canvas во вкладке chka.am → `clipboard.write(ClipboardItem)` настоящим кликом → Cmd+V в Gemini (точный файл любой пропорции). Хуже: снимок вкладки scale 1 → `upload_image`. Не жать Escape после «Загрузить файлы»; перед отправкой снимок «вложение на месте». [pp-12, pp-15 · L217, L221]
- Вставка картинки из JS (DataTransfer) во встроенном браузере Claude блокируется как утечка — так не обходить; защита может заблокировать и загрузку кадров через Chrome → нужен запасной путь. [s16, s23 · L95, L134]
- Полный размер — только кнопкой «Скачать изображение в полном размере» (файл в `gemini/in/` или ~/Downloads, 1536×2752); ссылка gg-dl отдаёт то 1536, то 768; снимки экрана для переноса картинок запрещены. [pp-3b · L182]
- Скачивание приходит через 20–120 с и иногда не доходит: брать только файл с mtime ПОСЛЕ клика (`find -newermt`), не `ls -t`; кнопка молчит — превью 1024 и один раз разрешить «несколько файлов». [без метки, s20, dl-1 · L44, L120, L264]
- Нет доступа к ~/Downloads (старый обход): fetch gg-dl → холст кусками → снимки → склейка с калибровкой цвета (`pogos-petros/gemini/transfer/`), сверка клеток ≤ 3 уровня. Хуже кнопки — только если её нет. [pp-3 · L181]
- Пока картинка рисуется, вкладку не трогать (navigate, «Новый чат») — генерация пропадает вместе с чатом; ждать `sleep` на Маке; `browser_batch` дольше ~90 с отваливается. [27.10 · L196]
- Pro ответил «cannot generate images» — это сбой, не лимит: пауза 3 мин → «Please try again: generate the edited image…» или новый чат с запросом короче. [заход 10 · L213]
- Лимит Pro ≈ 5–7 картинок за окно, потом модель сама падает на Flash-Lite: сначала главные кадры и маски, правки потом; что не успело — отметить в отчёте. [pp-4b · L188]
- Лимит Veo проверять ДО плана: пункт «Создание видео» серый (`aria-disabled`) = лимит; сброс ≈ через сутки после первого ролика серии. Нет Veo — запас из уже снятых; движок готовить так, чтобы новый ролик менял только файл. [pp-18 · L235]
- Заход «Veo до времени сброса» — только проверка и отчёт; аккаунт проверять JS по aria-label («Аккаунт Google: …»), не по картинке. [pp-20 · L245]
- Veo через Claude in Chrome: вложение перехватом input; готовый ролик — «Скачать видео» → `gemini/in/*.mp4`; после генерации чат молчит — перезагрузить чат, кнопка через 5–8 с. Сеть и порты Мака командами не «разведывать». [pp-21 · L246]
- Flow принимает новое сообщение, только когда закончил прошлое (■ = занят), иначе текст и вложение молча пропадают; бонусы одобрять по одной генерации. [s10 · L74]

## 4. Veo, видео-актёры, синемаграф
- Вход Veo — точный файл; первый кадр = последний = рисунок; продолжение — из последнего кадра прошлого ролика, совмещать со своим входом, а не с рисунком. [pp-17 · L233]
- «Вертикальное 9:16» в Veo = весь кадр 1:1 по пикселям; шоу «по всему зданию» — так, а не 16:9-кропом. [pp-15 · L222]
- Чего нет в рисунке, Veo «из ничего» не оживит: сначала правка Gemini «добавь только X», потом Veo из правки; видео брать целиком из правки. [pp-15 · L223]
- Вперёд–пауза–назад печь в сам файл видео (ffmpeg): отрицательная playbackRate в браузерах не работает. [pp-15 · L224]
- Veo: ответ может прийти «молча» (искать в списке чатов 2–5 мин, повтор не слать); проверять листом кадров по времени (поменял людей местами); «One continuous shot, no cuts» + «X слева, Y справа весь ролик»; если в конце предметов больше — петля туда-обратно. [pp-14 · L219]
- Увеличенный кусок для Veo: ×5–6 с фигурами ≥ 70 px — ок; ×7,5 — резкий мультик и подмена человека; из ролика брать только зону своего героя и удачный отрезок. [s21 · L123]
- Слово «fountain» на пустой площади дорисует фонтан: писать «water only inside the existing pool»; дальний город на видах сверху — в `--exclude`. [s13 · L84]
- На рисунок класть не кадр видео, а его отличие от медианы видео — иначе чужой оттенок и «стоящие» объекты Veo. [s7 · L59]
- Цвет видео на iPhone ≠ цвету картинок, пометка цвета лечит не до конца: видео хранит только ОТЛИЧИЕ от рисунка (серый 128, MV_DELTA) + калибровочная полоска (MV_CAL); кодировать с пометкой bt709; сравнивать с `?cine=0`. [s10, s14 · L72, L88]
- Старт видео на iPhone: держать в скрытом слое документа (1 px), muted + playsinline до src, `play()` на canplay с повтором и на первом касании. [s10 · L73]
- Жёсткий край маски видео на iPhone виден линией через кадр: куски у прямого края выкидывать (`--edge-drop`) или делать край очень мягким; «линию неба» ночной картинки — сглаживать. [s14 · L89]
- Отличие собирать в сетке кадра (1365) и пережимать в размер ролика (1364), для людей crf 18/24; иначе «прозрачное тело» и светлый контур. Проверять только снимком Chrome. [s21 · L122]
- Видео-актёр ночью и на закате: `ночь + (видео − день) × (ночь/день, размыто)`; где видео = рисунок — ошибка ровно 0; дневную текстуру писать и ночью. [pp-18 · L234]
- Дневной ролик людей ночью через «отношение» даёт призраков: ночью люди непрозрачные по силуэту, ночной клип = неподвижная ночная картинка. [s21 · L124]
- Голуби и люди ВНУТРИ видео дёргаются, в замедлении летят «в слоумо» и тают: в маску только листва, вода, ткань; серые капли вырезать по кадрам; птиц даёт движок; проверять счётчиком, не листом. [s11, s14 · L78, L86]
- Замедление ролика (minterpolate) — минуты на клип: кэшировать; логи фоновых запусков — с `PYTHONUNBUFFERED=1`. [s11 · L80]
- В облачном Chromium нет H.264: для проверок нужен WebM/VP9; движок выбирает по canPlayType, iPhone берёт mp4. [s7 · L58]
- Ролик получает `?v`, только если движок срезает запрос перед `.mp4`→`.webm`; проверять настоящей функцией из viewer.js через node. [s25 · L144]
- Видео в слое здания красит и небо куска: брать пиксель видео только там, где он отличается от рисунка (`showVideo.diff`). Тестовый сервер обязан отдавать Range (206), иначе видео не перематывается и «заморозка» шоу не работает. [pp-15 · L226]
- Ролики героев в проверках (?vt=1): длинный advance() идёт без событий браузера — перематывать ролик, только когда прежняя перемотка кончилась, снимок брать после __e2.pending() = 0; перемотка на каждом шаге — серия в 2–3 раза дольше и G6 «как повезёт». [p3b]
- Герой в закатном и ночном рисунке = версия + (ролик − день) × (версия / день, размыто) — движок считает тон сам, ручные карты тона не нужны; люди ночью — ночной рисунок (ролик через тон — призраки). [p3b]

## 5. Вырезка, слои, кайма, глубина
- scipy `binary_dilation/erosion(iterations=0)` = «до упора»: `grow: 0` сделал вырезку на весь кадр. Настройку, которая может быть 0, передавать через `if n > 0`. [06.10 · L22]
- Параллакс чинится замером объекта ОТНОСИТЕЛЬНО фона вокруг на крайних наклонах, не частей объекта между собой; плоскость крупного плана — `depthRaw` + своя карта. [06.10 · L25]
- «Резина» при повороте: карта глубины даёт вертикальному предмету разную глубину сверху и снизу. Крупные планы и интерьеры — почти плоские (`tiltK` 0,2). Сначала предлагать простое решение. [заход 8 · L203]
- Не перекрашивать объект масками повторно — перерисовать целиком (Gemini) и пересобрать вырезку: пять перекрасок статуи = «плохо вырезанный фон». [s20 · L115]
- Вокруг здания движок показывает САМ КАДР, подложка `_bg` — только под вырезкой +3 px: кайму чинить в слое здания, в кадре и в ночной картинке; сузил вырезку — проверь открывшуюся подложку. [s20 · L117]
- Кайма вырезки: ночью цвет края берётся из ночной картинки → светлый край гасить АЛЬФОЙ, но до 2/255, не до 0; у постамента кайма — бумага 2–4 px СНАРУЖИ контура. [pp-27 · L255]
- Серый ореол у крон и постамента — небо в env не доведено до силуэта: доводить небо до силуэта, проверять снимком без ветра. [s23 · L132]
- Пересохранение кадра в webp q92 меняет ВСЕ пиксели: «вне правки пиксель в пиксель» доказывать маской до кодирования; неизменённые кадры не пересохранять. [s16 · L97]
- Слои нового здания — теми же инструментами в своей папке; крупный план и интерьер — вырезка в `extra_box` + `sky.max_v`, иначе светлая стена считается небом. (В станке e2 — `stanok layers`.) [pp-4 · L185]
- Качание крон двигает только ПОДЛОЖКУ: дерево, попавшее в слой здания, стоит — крону перед sway перенести в подложку и убрать из альфы слоя здания. [pp-4c · L190]

## 6. Ночь, окна, фонари
- Ночь и закат = сам рисунок Gemini: правка «тот же кадр ночью» с точным файлом в новом чате совпадает 1:1 (2–4 px). Тогда `nightWins: false`, `nightLamps: []` — иначе код зажжёт квадратные окна и ореолы. [заход 10 · L212]
- Ночь Gemini в превью 1024 px — не замена кадра, а карта света поверх полного дневного рисунка (`night_from_gemini.py`), иначе карандаш мылится. [s4 · L47]
- Ночь Gemini приносит свою луну и нимб за статуей: небо брать вертикальным ходом по строкам. [s4 · L49]
- В маске окон и фонарей Gemini дорисовывает столбы и красит кроны «фонарём»: кроны отбрасывать по цвету рисунка, столбы рисовать в сам рисунок (день и ночь). [s4 · L48]
- Карту ночи размывать сильно (9 px), отдельно землю и небо; бумажную кайму вырезки ночью закрашивать цветом неба. [s7 · L56]
- Ночь из дня через фильтр движка темнеет дважды: фонари и подсветку рисовать с запасом + `nightLamps`, иначе ночь «мёртвая». [без метки · L38]

- Свет окон — только по окнам, найденным НА РИСУНКЕ (тёмные прямоугольники в ряд на фасадах), не по маске Gemini 1024 px; доказательство — оверлей поверх рисунка. [s14 · L87]

## 8. Погода, ветер, небо, вода
- Ветер «сдвигом выборки по маске дерева» затягивает в крону фон и рвёт штрих «лесенкой»: качать так, чтобы фон стоял (наветренный край неподвижен); маска крон — по рисунку (зелень + штрих), не по глубине. [s23 · L129]
- Всё, что меняется «по клеткам» (`floor`), на iPhone видно квадратами — только плавный шум. Землю держать в подложке, не в слое здания. Ветер ≤ ~9 px в мягкой маске кроны, трава стоит. Детали, растущие с плотностью, включать наверху в начале круга. Позы — только днём. [pp-11 · L216]
- Снег на предмете, который есть только в непогоду: править маску снега по контуру предмета (многоугольник ∩ альфа), крышу оставить. [pp-16 · L228]
- «Снежинка села на крышу» мерить по линии неба столбца (первая поверхность сверху), не правилом «ближе — ниже». [st-p2 · L281]
- Замер снега виртуальным временем в облачном Chrome ронял WebGL (e1.x) — мерить в настоящем времени. [s23 · L133]
- Дождь e1.62 недетерминирован: побайтно «до/после» не сравнивать, только с порогом; в e2 осадки считаются от виртуальных часов и номера частицы (G6). [st-p0 · L272]
- Полоса неба (`sky.band`) — только НАД объектом, иначе облако на груди статуи; проверять на снимке кадра. [05.10 · L21]
- Воду запекать в картинку: синяя заливка движком поверх штриховки даёт «узор». [без метки · L32]
- Вес вынимания кроны из подложки — не мягкая α маски: край с α < 1 оставляет на месте «призрак» (1 − α)·(кадр − заливка), тёмные штрихи контура. Вес = 1 над кроной и на ~5 px шире, дальше мягко; тёмные штрихи у кроны (V < 150 в 6 px от неё) — тоже крона. [p3a]
- Окраску дня (небо, зелень по неподвижным маскам окружения) считать ДО сдвига кроны: порядок крючков = порядок эффектов в `effects.schema.json` (ветер после tod). Иначе светлый лист над чужим небом красится как небо — белые «искры» на кромке. [p3a]

- Текст инфо-точки — одной строкой, «заголовок» = первая короткая фраза; новые текстовые поля — сначала в схему (i18n + длина). [pp-5 · L238]

- «Плашка» на телефоне — два элемента: `#barTitle` (название) и `#frameCap` (подпись кадра); править оба. [zv2-2 · L258]
