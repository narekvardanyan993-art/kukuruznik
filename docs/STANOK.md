# STANOK — станок chka.am: один движок, один конвейер

Спецификация. Написана 10.11.2026 (шаг 3/10 Fable-недели) по `docs/ENGINE-BUGS.md`; движок e1.62, ветка test/depth-photo.
**Кода станка ещё нет** — его пишет шаг 4 (раздел 7). Всё, что названо командой `tools/stanok.py …` или «модуль e2», — задание шагу 4.
**Изменение плана 10.11 (П1):** Ленин заморожен на `engine-k/` вместе с Кукурузником и на e2 не переезжает; полигон и переезд — только Погос-Петрос. Ответы Нарека на вопросы §9: 1Б 2да 3 — эмуляции достаточно 4Б.
Числа с пометкой «старт» — стартовые, уточняются первым замером. Скилл для агентов: `.claude/skills/chka-stanok/SKILL.md`.

**Цель.** Новое здание (5–6 кадров; день, закат, ночь, снег, дождь, до/после; ≥ 2 изюминки) — за ≤ 3 захода агента и ≤ 1 час Нарека.
Баги, которые чинили по много раз, ловят автопроверки (гейты) до Нарека.

## 0. Семь правил станка

1. **Видимое рисуют Gemini и Veo.** Код только двигает, режет, смешивает, зажигает и гасит.
2. **Один эффект — один режим.** Не подходит кадру — эффект выключен. Второй режим не заводим.
3. **Мелкое движение — качественно или никак.** Нет Veo-ролика или он плохой → предмет стоит неподвижно в рисунке.
4. **Файлы сайта (`frames/`) пишет только станок** из мастеров. Руками и одноразовыми скриптами — никогда.
5. **Любая правка рисунка — через `insert`**, и она попадает во все версии кадра (раздел 3).
6. **Настройки нет в схеме → сборка падает громко.** «Молча не дошло» больше не бывает.
7. **Не проверено гейтом — не готово.** У каждого гейта есть красный случай, который доказывает, что он ловит.

Чего в станке нет (решения Нарека 10.11): машин, звуков, людей и воды кодом, стоящих статичных людей, второго режима у эффекта.

## 2. Архитектура движка e2

### 2.1 Что не так сейчас (факты e1.62)

- `viewer.js` 4488 строк + `details.js` 2179; 99 флагов `CONFIG.*`; шейдер собирается склейкой строк с ветками «у Кукурузника нет — шейдер прежний».
- Ветер × 3 (`SWAY`, `SWAY_SOFT`, `NO_SWAY`), фонтан × 2 (`fountains`, `pix jet/ripple`), ночь × 2 (свет в рисунке / `nightWins` + `nightLamps`).
- `prep.js` получает выборку настроек — новая настройка молча не доходит. Сборка при ошибке схемы однажды упала молча.

### 2.2 Устройство

**Заморозка Кукурузника и Ленина.** `engine-k/` — копия движка e1.62 (сделана в П0). На неё смотрят Кукурузник и Ленин — живые страницы и бета (`FROZEN` в `tools/build_pages.py`). Требование «шейдер Кукурузника побайтно прежний» снято, `engine-k/` не правится. В нём же остаётся «библиотека» всего старого кода (машины, фигуры, фонтаны, фонари и окна кодом, статуя). Перевод Кукурузника или Ленина на e2 — потом, если дёшево; сейчас не планируется.

**Модули.** Исходник — `engine/src/`, сборка `tools/build_engine.py` склеивает их в один `engine/viewer.js` (без npm и сборщиков; один файл на телефоне, как сейчас).

```
engine/src/
  core/clock.js      единственный источник времени и случайности (раздел 6, G6)
  core/gl.js         контекст, текстуры, потеря контекста, сборка шейдера из кусков эффектов
  core/frames.js     загрузка кадров по manifest, память (текущий + соседние)
  core/perf.js       ступени качества (раздел 5)
  core/ui.js         кнопки, панель, плашка, точки, язык
  fx/<имя>.js        один файл — один эффект
effects.schema.json  ключи, типы, диапазоны, значения по умолчанию, нужные файлы — ОДИН источник для схемы (Python) и движка (JS)
```

**Эффект** — объект с одним набором полей:
`name` · `files(frame)` (какие файлы кадра нужны) · `glsl` (кусок шейдера в один из 5 фиксированных крючков) · `init(frame, cfg)` · `step(t, dt)` · `low` (что делает на слабой ступени: `off` или `lite`) · `cost` (очки бюджета, раздел 5).
Эффект, которого у здания нет, в шейдер не попадает вовсе — мёртвых веток нет.

**Крючки шейдера — порядок жёсткий:** 1) `uv` — наклон и ветер; 2) `base` — рисунок + подложка + здание + актёры; 3) `tod` — полдень, закат, ночь, огни; 4) `weather` — пасмурно, мокро, снег лёг; 5) `post` — длинные тени заката. Осадки — отдельный проход частиц в той же сцене.

**Эффекты e2 (11 штук, у каждого один режим):**

| Эффект | Что делает | Откуда переезжает | Что НЕ переезжает |
|---|---|---|---|
| `parallax` | наклон по глубине; `kind: close/interior` → почти плоско | MAX_SHIFT, ZOOM_NEAR, `tiltK`, BUILDING_DEPTH_PIXEL (всегда вкл.) | `bldDepth`, `depthRaw` → опции шага `layers` |

Вода и фонтаны — это `actors` с роликом Veo. Отдельного «фонтана» в движке нет.

**Версия движка закрепляется за зданием.** Каждая выкладка движка — неизменяемая папка `e/<версия>/` на сайте; страница здания ссылается на свою версию. Новый движок не может сломать живое здание, круг «движок ждёт здание, здание ждёт движок» исчезает, кэш сбрасывать не нужно (адрес новый). Здание переходит на новую версию командой `publish_building.py <slug>` после своих зелёных гейтов. Кукурузник = здание, закреплённое на `engine-k/`.

### 2.3 building.json format 2

```json
{
  "format": 2,
  "id": "pogos-petros",
  "meta": {}, "text": {}, "facts": {}, "links": {}, "live": {}, "card": {}, "sale": {}, "postcard": {},
  "look": { "frameSize": [768, 1365], "sunSide": "left" },
  "effects": {
    "weather": { "snow": { "accumS": 12, "meltS": 30 } },
    "wind":    { "gusts": "default" },
    "tod":     { "noon": true }
  },
  "frames": [
    { "name": "pogos_a", "kind": "wide",
      "caption": { "hy": "…", "ru": "…", "en": "…" },
      "hotspots": [],
      "effects": {
        "tod":     { "sun": { "day": [0.2, 0.1], "sunset": [0.1, 0.4], "moon": [0.8, 0.1] } },
        "wind":    { "amp": 1.2 },
        "weather": { "rain": true, "snow": true },
        "actors":  [ { "id": "old-man", "emotion": true, "rect": [0.28, 0.68, 0.62, 0.855],
                       "media": { "day": "vid_a_old", "rain": "vid_a_old_rain", "snow": "vid_a_old_snow" } } ],
        "show":    { "type": "video", "video": "vid_a_show", "t": [1, 11], "cam": {} }
      } }
  ]
}
```

Правила:
- Блока `tuning` и сырых флагов CONFIG **нет**. Всё — в `effects.<эффект>` здания (умолчания) и кадра (отличия).
- `kind`: `wide` · `close` · `interior`. `close` и `interior` → наклон ×0,2 сам; `interior` → погоды и ветра нет сам.
- Погода, полдень, солнце — на уровне кадра у всех зданий. `sun.sunset` обязателен у каждого кадра и обязан попадать в небо (маска неба).
- Неизвестный ключ, не тот тип, число вне диапазона, файла нет в `manifest.json`, меньше двух героев на здание → **сборка останавливается**, код выхода ≠ 0, первая строка по-русски: `ОШИБКА building.json: кадр 2 (pogos_b), effects.wind.ampl — такого ключа нет. Есть: amp, leaves.` На диск ничего не пишется.
- Сборка ставит штамп `frames/build.json` (sha настроек, версия движка, время). Снимки и гейты отказываются работать, если штамп не совпал с текущим building.json, — «снимки показывают старое» больше невозможно.
- `prep.js` получает весь проверенный объект `effects`, а не выборку.

## 3. Матрица версий кадра

Кадр — это не одна картинка, а набор. Правка, сделанная только в одной, — самый частый повторявшийся баг (собака пропадала на закате, актёров не было ночью).

| Версия | Мастер | Файлы сайта | Что с ней делает `insert` |
|---|---|---|---|
| день | `day.png` | `<кадр>.webp` | пиксели правки по мягкой маске |
| подложка | `bg.png` | `_bg.webp`, `_bg_depth.webp` | `--layer ground`: те же пиксели; `--layer building`: не трогает |
| слой здания | из day − bg | `_building.webp` | `--layer building`: пиксели + альфа; `ground`: вырезает, если правка перекрывает здание |
| закат | `sunset.png` | `_sunset.webp` | день-правка × отношение «закат / день» вокруг (тон) |
| ночь | `night.png` | `_night.webp` | `ночь + (правка − день) × отношение «ночь / день»`; свет на правке — только правкой Gemini ночной вырезки |
| снег | `snow.png` | `_snow.webp` (маска) | маска пересчитывается в прямоугольнике: верх предмета — снег; `--wx snow` — предмет виден только зимой |
| глубина | из day | `_depth.webp` | предмет ставится на глубину земли у его нижней кромки |
| маски | из мастеров | `_env`, `_lights`, `_crown`, `_land` | пересчёт в прямоугольнике |
| актёры | `veo/<id>/` | `vid_*`, `*_mask`, `*_tone` | если правка задевает прямоугольник актёра — стоп с сообщением: актёра нужно переснять |

Как работает:
- `stanok insert <slug> <кадр> <правка.png> --box x,y,w,h --layer ground|building [--wx rain|snow|after] [--id имя]`.
- Шаги: выравнивание правки к вырезке дня → маска отличия → запись во все строки таблицы → запись в `work/<slug>/journal.json` (id, прямоугольник, sha до и после по каждой версии).
- **Журнал переигрывается.** Пришёл новый мастер (например, новая ночь от Gemini) → `stanok build` заново накладывает все вставки журнала. Вставка не теряется никогда.
- Актёры видны во всех версиях автоматически: `stanok actor` сам считает карты тона заката и ночи для прямоугольника (сейчас это ручные `vid_b_dog_night_tone.png`).
- Купленная надпись — тот же `insert` с `--inscription` (сейчас `deliver_inscription.py`).
- Правило мест: надписи и вставки не кладутся на святое (стены церкви, портал, алтарь) — в `story.md` есть список запретных зон, `insert` сверяет прямоугольник.

## 4. Эффекты (по решениям Нарека 10.11)

Обязательный минимум здания: день, закат, ночь, снег, дождь, до/после. Ветер — если в кадре есть деревья. Актёры — по лимиту Veo, но не меньше двух на здание.

### 4.1 Ночь (`tod` + `lights`)
- Ночной кадр целиком рисует Gemini: правка «тот же кадр ночью» с точным файлом в новом чате; окна и фонари горят в рисунке; свет ложится на стены, землю и воду. Фонарей и ореолов кодом нет («наклейки»).
- Маска огней считается сама: где ночь заметно ярче и теплее «дня × затемнение». Пятна → отдельные огни (до 64 на кадр), у каждого тип `window` или `lamp` (по размеру и форме).
- По кнопке «Ночь»: кадр темнеет с погашенными окнами (в пятне окна — дневной пиксель в ночном тоне), затем окна зажигаются **по одному** в случайном порядке, все за ≤ 6 с. Конечное состояние — ровно рисунок Gemini.
- Дальше мягкое мерцание: плавный шум ±4–6 % яркости у части огней (никаких клеток — шум по огню целиком), раз в 20–40 с одно окно гаснет или зажигается. Фонари — только «дыхание» ±3 %.
- Свечи и иконы в интерьере — те же `lights`, тип `flame`, работают в любое время суток.
- Приёмка ночи отклоняет: чужую луну, нимб за объектом, сдвиг относительно дня (G9), кайму вырезки, которая светится (G2).

### 4.2 Снег и дождь (`weather`) — «падает НА поверхности»
Сейчас: кружки на отдельном 2D-холсте поверх всего, без глубины — «белые шарики из ниоткуда». Будет:
- **Частицы живут в сцене.** У снежинки и капли есть глубина. Частица дальше здания — здание её закрывает; ближние крупнее и быстрее, дальние мельче и гуще. Картинки частиц — листы Gemini (`show_flake_*`, `show_rain_*` уже есть), код их только двигает и красит под время суток.
- **Посадка.** Станок заранее считает карту посадки `_land` (из глубины и маски снега): где на пути частицы есть верх предмета — крыша, карниз, земля, будка. Снежинка, дойдя до своей поверхности, гаснет за 0,2 с на ней, а не летит сквозь кадр. Капля даёт маленький всплеск на земле (всплески уже есть в e1.62).
- **Снег ложится там, куда падает.** Маска снега — из зимнего рисунка Gemini (зима − день). Проявляется по времени сверху вниз: сначала кромки крыш и верх предметов (формула «шапок» Кукурузника по глубине задаёт порядок), потом плоскости. Копится ~12 с, тает ~30 с.
- Начало погоды: частицы входят сверху и из-за края по ветру, с нарастанием густоты; середина экрана пустой не «заселяется».
- Дождь: мокрые стены и земля темнее (как сейчас), после дождя — радуга-картинка Gemini (актёр `after`).
- Погода задаётся по кадру. `interior` — без погоды. Кадр, где зима уже нарисована, — только частицы.
- Герои в непогоду не замирают: у каждой изюминки свои ролики `rain` и `snow` (газета, воротник, пар изо рта, собака в будке).
- Предмет, который есть только в непогоду (будка, зонт), — `insert --wx`; снег на нём объёмный, рисует Gemini.

### 4.3 Ветер (`wind`) — без размазывания фона
Причина всех размазываний: сдвигали выборку общей картинки — в крону затягивало небо и дома. Будет:
- На шаге `layers` кроны вырезаются в **отдельный слой с прозрачностью** (`_crown`), а подложка под краем кроны дорисовывается на ширину качания + 3 px (тонкое кольцо, обычная заливка по соседям).
- Движется только слой кроны: низ стоит, верх уходит до `swayMaxPx` (9 px кадра, старт). Пиксель вне кроны берётся из неподвижной подложки — размазать нечего. Это ловит G1.
- Крона, которая на телефоне меньше 40 px (старт) или сидит в слое здания, не качается — ветер на таком кадре показывают листья.
- Листья в порыв — картинки Gemini (`leafFly`), срываются с крон и из-за края.
- Трава, кусты, флаги кодом не качаются. Нужен флаг или бельё на ветру — это актёр Veo.

### 4.4 Вода и фонтан — Veo или ничего
- Вода нарисована в кадре. Движение — только ролик Veo поверх (актёр `kind: water`), петля без шва, пиксели только там, где ролик ≠ рисунок.
- Нет хорошего ролика → вода стоит. Струй, ряби и течения кодом нет.
- Зимой фонтан выключен и замёрз (картинка-вариант `snow`).
- В промпте Veo не писать «fountain» на пустой площади — дорисует фонтан (lessons s13).

### 4.5 До/после (`show`)
- Ролик Veo «было → снос → стало», продолжение — из последнего кадра предыдущего. `stanok show` запекает «вперёд–пауза–назад» в файл (обратной перемотки в браузерах нет), пишет маску «ролик ≠ рисунок» — небо не красится.
- Одно шоу на кадр, запуск кнопкой. На время шоу — день; позы актёров гаснут (собака не «телепортируется»).
- Шоу по теме здания (церковь — без салюта) и с развязкой: сцена темнеет перед главным моментом. Есть хотя бы на одном кадре здания; цель — на каждом.
- Тип `parade` (флаг Армении) остаётся как второй вид шоу для зданий, где уместен праздник.

### 4.6 Актёры с эмоцией — стандарт, не бонус
- **У каждого здания ≥ 2 изюминки** — живой персонаж с понятной эмоцией: собака, старик с голубями, пара, кошка, мальчик с воздушным змеем. Сборка без двух героев с пометкой `emotion: true` не проходит (G8).
- У изюминки обязательно: петля днём; свои варианты в дождь и в снег; видна на закате и ночью (тон считает станок); на телефоне занимает ≥ 6 % высоты экрана (старт) и не закрыта интерфейсом (G7).
- Желательно: реакция на тап (как собака на кадре B) и на погоду рядом.
- Люди — сидящие или занятые делом, мелкие и средние. Стоящих столбом нет. На крупных планах людей нет — там птица, кошка, блик.
- Veo: вход — вырезка из рисунка без увеличения (увеличенный кусок Veo перерисовывает в мультик), первый кадр = последний. Ролик хранит отличие от рисунка + калибровочную полоску (цвет на iPhone).
- Птиц в небе и на карнизах даёт движок (`sky`), не Veo (в замедленном ролике птицы «в слоумо»).

### 4.7 Короткие правила
- **Мелкое движение — качественно или никак**: Veo-ролик, прошедший гейты, или неподвижный рисунок. Кодом можно только небо (облака, птицы, самолёты), огни и осадки.
- **Машин нет.** **Звуков нет.**
- **Крупные планы и интерьеры почти плоские** (`kind` → наклон ×0,2): глубина там даёт «резину».
- Каждый кадр: ≥ 2 % экрана телефона меняется за 5 с (G10), нет кадра, где половина — пустое небо или площадь без детали.

## 5. Производительность

### 5.1 Бюджет кадра (старт, уточняется замером в прогоне 4.6)

| Что | Полная ступень | Лёгкая | Минимальная |
|---|---|---|---|
| цель fps (телефон 390×844) | 60, не ниже 50 | не ниже 30 | не ниже 24 |
| плотность пикселей (dpr) | до 2 | до 1,5 | 1 |
| проходов рендера | 1; второй только на закате (тени) | 1 | 1 |
| частицы осадков | до 400, в сцене | до 150 | до 60 |
| ролик-актёр одновременно | 1–2 | 1 | 1 (главная изюминка) |
| ветер, тени облаков, события неба | да | ветер нет | нет |
| кадров в памяти видеокарты | текущий + 2 соседних | текущий + 1 | текущий |

- Каждый эффект объявляет `cost`. Сборка считает сумму по кадру × состоянию и число выборок текстур на пиксель в собранном шейдере; выше бюджета → ошибка сборки с названием самого дорогого эффекта.
- Кадр видео загружается в текстуру только когда пришёл новый кадр ролика (20 раз в секунду, не 60).
- Фонари ушли в рисунок → второй проход ночью не нужен (в e1.62 сцена всегда рисуется в два прохода: в текстуру, потом на экран).
- Изюминки отключаются последними: «мы продаём эмоции».

### 5.2 Режим для слабых телефонов
- Ступень выбирается сама: первые 2 с — замер fps (механизм `perfLevel` уже есть: два медленных окна подряд → ступень вниз; ровный fps → назад). Стартовая подсказка: память и число ядер устройства, где браузер их отдаёт.
- Порядок отключения: частицы ÷2 → dpr 1,5 → ветер и тени облаков → dpr 1 → события неба → второй актёр.
- Кнопки в интерфейсе нет (на телефоне минимум интерфейса). Проверка: `?tier=lite|min`.
- iPhone в энергосбережении держит 30 fps — это норма, ступень не снижается (уже учтено в e1.62).

### 5.3 Разбор тормозов: Погос-Петрос, кадр 1, снег
Кадр A в снег сейчас одновременно крутит: ролик старика (`vid_a_old_snow`) + картинку-вариант, 2D-холст снежинок поверх WebGL, снежную ветку шейдера, плывущие облака (`drift`), листья в порыв, два прохода рендера при dpr 2; ночью ещё мерцание (`nglow`).
1. Повторить: `fps_check.mjs` с ключами кадр/погода, замедление процессора ×4 и ×6, телефон 390×844.
2. Разметить время по частям кадра (`?prof=1`): погода, частицы, загрузка видео, проход сцены, второй проход, детали.
3. Выключать по одному (`?off=precip,actors,snow,post,sky`) → таблица «что сколько стоит» в `report/perf_a_snow.md`.
4. Подозреваемые по порядку: (а) 2D-холст — на каждую снежинку два рисования и новая строка цвета, плюс наложение холста на WebGL; (б) загрузка кадра видео каждый кадр экрана; (в) снежная ветка — лишние выборки текстур на пиксель при dpr 2 в двух проходах; (г) всё вместе без бюджета.
5. Чинить два самых дорогих. Ожидаемо закрывается самим e2: частицы в сцене (а), загрузка видео по новому кадру (б), один проход (в).
6. Готово, когда: кадр A в снег ≥ 50 fps на ×4 и ≥ 30 fps на ×6 в лёгкой ступени (G4), и Нарек не видит рывков на iPhone.
Честно: эмуляция на Маке ≠ слабый телефон. Нужен один реальный замер (вопрос В3).

### 5.4 Меню-панель
Сейчас на телефоне (`engine/page.html`): перо рисует контур 800 мс, лист проявляется 700 мс с задержкой 380 мс, строки появляются начиная с 650 мс + 70 мс на каждую, кнопки — с 760 мс → первое содержимое через ~0,7 с, всё — через ~1,5–2 с. На ПК цифры близкие (770 / 800 / 635 + 54).
- Содержимое видно и нажимается через **≤ 250 мс** после тапа. Перо дорисовывает контур поверх как украшение и ничего не задерживает.
- Вся анимация ≤ 450 мс; строки — шаг ≤ 20 мс, всего не больше 120 мс; закрытие — зеркало, ≤ 60 % открытия (правила `docs/ANIMATION.md` остаются).
- Три кнопки снизу не меняются (Нарек: понятные). Проверка — G12.

### 5.5 Плашка с названием на телефоне
- При входе на кадр плашка (название + подпись кадра) видна **3 с**, гаснет за 300 мс, остаётся маленькая бирка. Тап по бирке — снова на 3 с.
- Одна плашка вместо двух (`#barTitle` и `#frameCap`); подписи кадров — у всех зданий.
- Плашка и бирка не ложатся на прямоугольники изюминок: место выбирается по карте занятости кадра (та же, что у открытки). Во время шоу скрыта.

## 6. Гейты — автопроверки до Нарека

Запуск: `stanok check <slug> [--frames a,b] [--gate G1,G7]`. Всё — в настоящем Chrome, телефон 390×844, виртуальное время. Отчёт — `tests/<slug>/report/gates.md` + листы снимков.
`stanok check --selftest` для каждого гейта сам вносит известную поломку и ждёт красный; гейт, который не покраснел, считается сломанным. Самопроверка идёт перед каждым прогоном шага 4.
Время: один дом ≤ 10 мин на Маке; в облачной VM — только изменённые кадры (`--frames`), иначе > 20 мин (правило проекта).

| Гейт | Что ловит | Как работает | Красный случай (самопроверка) |
|---|---|---|---|
| **G1 ветер** | размазывание фона за кронами | два снимка в один момент виртуального времени: ветер на пике порыва и без ветра. Вне маски крон, расширенной на `swayMaxPx` + 2 px, отличий быть не должно (порог шума). Внутри — нет «лесенки»: разрыв штриха по строкам ≤ 1 px | `?break=wind` включает старый сдвиг выборки по мягкой маске → небо у кроны меняется → красный |
| **G2 кайма** | светлая кайма вырезки, свечение каймы ночью | (а) по файлу: кольцо 3 px у края альфы слоя здания — доля «бумажно-светлых» пикселей ≤ 0,5 %; (б) по рендеру: 2 крайних наклона × день и ночь — вдоль контура нет линии ярче обеих сторон; (в) вырезка < 90 % кадра | тестовый слой с белым кольцом 2 px → красный; вырезка на весь кадр (`grow: 0`) → красный |
| **G3 вставка** | вставка не во всех версиях | для каждой записи журнала: в каждой версии (день, подложка/здание, закат, ночь, снег) прямоугольник изменился относительно «до»; на рендере 5 кнопок предмет виден (отличие от сборки без вставки ≥ порога) | вставка с тестовым ключом `--only day` → красный на «Закате» и «Ночи» |
| **G4 fps** | тормоза на слабом телефоне | каждый кадр × 5 кнопок: замедление процессора ×4 → ≥ 50 fps в полной ступени; ×6 → ≥ 30 fps в лёгкой; ступень сама снижается за ≤ 5 с.
