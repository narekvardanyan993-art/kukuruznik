# Չկա — здания, которых больше нет

Сайт-альбом снесённых зданий Еревана. Первое здание — «Кукурузник».

## Что это за проект и для кого

Здание, которого больше нет («Кукурузник», Дом молодёжи в Ереване),
восстановлено в 3D и открывается по ссылке в браузере. Человек крутит
его на 360°, приближает, заглядывает внутрь, читает историю. Первый из
серии таких зданий — дальше планируются другие снесённые дома Еревана.

Выкладывается бесплатно как контент для личного армянского TikTok
владельца — так же, как это делают моддеры GTA-Armenia: сначала
доверие и охваты, вопрос продажи отложен на потом.

Владелец (Нарек) код не читает — с ним нужно говорить простыми словами,
без названий функций и файлов. Он же — главный (и почти единственный)
человек, кто открывает сайт «с иконки на домашнем экране» iPhone;
обычные зрители открывают ссылку прямо в браузере из TikTok.

## На чём собрано

Чистый HTML/CSS/JS, без фреймворков. Рендер — Canvas 2D.

Жёсткие технические ограничения, проверенные на практике (нарушать
нельзя, каждое стоило отдельной поломки):

- **WebGL и Three.js запрещены** — не работают на iPhone владельца.
- **SVG с пересборкой DOM каждый кадр запрещён** — браузер не тянет.
- Цель — 60 кадров в секунду на iPhone. Ощущение «дорого» даёт
  плавность и инерция, а не визуальные эффекты.
- Стиль изображения — рисунок от руки: видимая линия, двойная обводка,
  штриховка на теневой стороне, лёгкая краска поверх. Не фотореализм.

Подробные технические правила (пороги отсечения граней, порядок кадра,
почему движок не разбит на настоящие ES-модули и т.д.) — в
`docs/PRAVILA.md`. Читать перед любой правкой рендера.

## Где точка входа и как запускается

Две точки входа:
- **`index.html`** в корне — главная «Չկա»: первый экран (архивное фото
  превращается в карандашный рисунок) и карточки зданий. Стиль альбома —
  `assets/hub.css`, рамки и превращение — `assets/hub.js`.
- **`kukuruznik/index.html`** — 3D-модель. Сама подгружает
  `kukuruznik/css/style.css` и три файла движка из `kukuruznik/js/` с
  версией сборки в адресе, чтобы телефон не застревал на старой версии.

Старые ссылки: корень сайта теперь главная, модель — по `/kukuruznik/`.
`404.html` отправляет любой несуществующий адрес на главную.
Корневой `version.txt` (`hub-…`) нужен старой закэшированной странице
модели: она увидит расхождение версий и один раз перезагрузится на главную.

Домен chka.am ещё НЕ подключён. Когда будет готов DNS — добавить файл
`CNAME` с одной строкой `chka.am` и указать домен в настройках Pages.
Раньше времени CNAME не класть: сайт начнёт уводить на неработающий адрес.

Публикуется на **GitHub Pages**:
- Живой сайт: https://narekvardanyan993-art.github.io/kukuruznik/ (главная)
- Модель: https://narekvardanyan993-art.github.io/kukuruznik/kukuruznik/
- Будущий домен: https://chka.am/
- Репозиторий: https://github.com/narekvardanyan993-art/kukuruznik

Локальный просмотр — двойной клик по `start.command` (поднимает сервер
на 8777, печатает адрес для того же Wi-Fi, чтобы проверить с телефона).

## Как устроены файлы: что за что отвечает

```
index.html            ГЛАВНАЯ «Չկա»: первый экран и карточки зданий
404.html              любой битый адрес -> на главную
version.txt           версия главной (для старых закэшированных страниц)
assets/               общий стиль альбома: hub.css, hub.js, бумага, иконки,
                      картинки первого экрана; assets/source — их исходники
tools/images.py       делает лёгкие картинки из исходников (первый экран, карточки)
kukuruznik/           ВСЁ, что видит зритель модели Кукурузника:
  index.html            точка входа модели: разметка, загрузчик, кнопка «Չկա» назад
  card.webp             рисунок для карточки на главной
  manifest.json         полноэкранный режим на телефоне
  version.txt           номер сборки — им страница проверяет, не устарела ли
  css/style.css         стили и анимации интерфейса модели
  js/engine.js          СОБРАННЫЙ файл движка (из src/engine) — не править
  js/model.js           СОБРАННЫЙ файл модели (из src/model) — не править
  js/controls.js        управление (вращение пальцем/мышью) — правится напрямую
  icons/                иконки модели
build.py              склеивает src/ в kukuruznik/js/, проставляет версию
src/engine/*.js       ИСХОДНИК движка — правь только здесь
src/model/*.js        ИСХОДНИК 3D-модели — правь только здесь
photos/               референсные фотографии Кукурузника
docs/                 документация
```

Подробная карта, что делает каждый кусок `src/engine/*.js` и
`src/model/*.js` (по файлам, с числом строк) — в `docs/CARTA.md`.

Журнал всех сборок, что менялось и почему — в `docs/LOG.md`. Он растёт
с каждой сборкой; новую сессию туда лезть целиком не нужно — смотри
последние 100–150 строк, если нужен контекст «где остановились».

## Что НЕЛЬЗЯ трогать и почему

- **`js/engine.js` и `js/model.js` руками не редактировать.** Это
  собранные файлы — правки в них пропадут при следующей сборке. Правь
  только `src/engine/*.js` и `src/model/*.js`, потом `python3 build.py`.
- **WebGL/Three.js не подключать** — на телефоне владельца не работает,
  проверено.
- **Порог отсечения задних граней (0.15) не понижать** — опускали до
  0.07, башня стала прозрачной.
- **Порядок отрисовки кадра не менять местами** (небо → земля и тени →
  поверхности → очередь по глубине → вывески → воздух) — иначе тени
  лягут поверх домов.
- **Другие проекты владельца не трогать** (IQ OS, Quiet Machines, Tech
  Insider и т.д.) — это отдельная папка/репозиторий, здесь работа
  только над «Кукурузником».
- Полный список технических «железных правил» — в `docs/PRAVILA.md`.

## Текущее состояние

**Работает:** сайт в обычном браузере (Safari, Chrome) — на телефоне и
на компьютере. Вращение, приближение, смена времени суток, звук,
кольцевое меню, все анимации — всё проверено и рабочее. Живой сайт
обновляется через GitHub Pages за десятки секунд после заливки.

**Сломано:** запуск с иконки на домашнем экране iPhone («на экран
Домой», standalone-режим). Интерфейс и меню появляются, сама 3D-сцена
не рисуется — экран синий, пустой. Известно точно: сцена при этом
живёт (счётчик fps реагирует на движение пальцем), холст нужного
размера и его пиксели закрашены — картинка не доходит до экрана,
что-то на стороне Safari не выводит слой. Статическое снятие
`overflow: hidden` (сборка 62) не помогло, хотя тот же приём, применённый
через JS ПОСЛЕ первой отрисовки, на телефоне сработал. Рабочая гипотеза
и план следующих шагов — в конце `docs/LOG.md`.

Это не мешает публикации в TikTok: зрители открывают ссылку в обычном
браузере, где всё работает. «На экран Домой» добавляет только сам
владелец.

**Недоделано:**
- Точный текст/ссылка на TikTok-канал владельца для указания в
  приложении — не пришёл от владельца, не дожат.
- Возможная более глубокая перерисовка деревьев (тени, детали) — было
  отложено, актуальность после атмосферной правки утра не проверена
  с владельцем.
